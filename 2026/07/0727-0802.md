- 何もデータが入っていないことと、空文字列が入っていることは別物であることを確認した。箱自体が空っぽの状態と中に空の箱が置いてある状態は別ということ
- 箱自体が空っぽ状態: `NaN`・`NULL`・`None`（未入力・データが存在しないこと）
- 中に空の箱が置いてある状態: 文字列が0の「文字列というデータ」が入っている
- `np.nan`: 欠損値（Not a Number）という数値データそのものを表す単一の値
- 前置アンダースコア1つ `_` の意図: 内部用（プライベート）、他から呼ばないでね、というメッセージ
- `@property`（プロパティ）
- 特徴①ReadOnlyにできる、参照はできるが変更はできない。外部から変更をさせない
- 特徴②外部からはまるで普通の変数にアクセスしているかのように扱えるようになる。
- 特徴③そのメソッドは getter になる。`@メソッド名.setter`と`@メソッド名.deleter` でデコレートされた関数がそれぞれ setter と deleter になり、値の代入・削除を行なう際に呼び出される。

```python
# @property がある場合（カッコ不要）
indices = config.target_indices

# @property がない場合（カッコ必要）
indices = config.target_indices()
``` 

```python
class PipelineConfig: 
    def __init__(self, name: str): 
    # 外部から直接触ってほしくない実体（メッセージ） 
        self._name = name 

    @property 
    def name(self) -> str: 
    # 外部に公開する読み取り専用窓口（制御） 
        return self._name 
```

- `@property` が付いたメソッドは、引数（self 以外の引数）を受け取ることができない
- `(*args, **kwargs) `: 「どんな引数が渡されても、すべて柔軟にまとめて受け取る」 ための特別な構文で、関数を定義するときに `*args` と `**kwargs` を指定しておくと、引数の数や渡し方が決まっていなくてもエラーにならずにまとめて受け取ることができる
- `*args`: 位置引数 (Arguments)・タプル形式でデータ受け取り
- `**kwargs`: キーワード引数 (Keyword Arguments)・辞書形式でデータ受け取り
- `@staticmethod` の役割: 「このメソッドは self（クラスの内部状態）を使わない、独立した処理」と Python や他の開発者に明示し、余計な self の受け渡しを無くすこと
- `@staticmethod` を付ける理由は、self（インスタンス自身）を引数として必要とするかどうかの違いによる
- Pythonにおいて、`@` から始まる記法（デコレータ）は、「その直下で定義された関数を、上の関数に引数として渡す」という文法ルール
- 関数の内部にコメントを書いているのと、外部に書いているのが混在していて何の違いかを調べて、目的の違いが分かったので使い分けていく
- Docstring: 関数ブロックの 1行目（内部） に記述し、「この関数が何をするか（仕様）」 を説明する
- Comment: 関数の 直前やコードの途中に記述し、「なぜその処理をしているか（補足・背景）」 を記述する
- 人間の目にはどちらも「が」に見えても、プログラムは文字コードで判定するため、"が" と "か"+"゛" の違いを判別する。この場合、検索やデータ比較で不都合が起きるので、どちらか一方の形式に揃える作業である正規化が必要になる。つまり、プログラムが処理する内部データ（バイナリ/文字コード）のズレを埋める作業が正規化ということ。 
- D（Decomposition = 分解）: 濁点やアクセント記号をバラバラに分解
例: 「が」→「か」 ＋ 「 ゛」
- C（Composition = 合成）: 分解できるものは1文字にギュッと合体させる
例: 「か」 ＋ 「 ゛」→ 「が」
