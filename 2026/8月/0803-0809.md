## 8/5(水)

### 自学

- ぶつかった課題: 与えられた整数を渡すと、1からnまでのXORの計算を行なう関数の実装において、与える整数が大きいとループ処理が膨大になり、時間がかかってしまった、または、計算が途中で終了し、エラーとなった
- 解決策: 連続する 4 数の組（例: 1,2,3,4）を XOR すると常に 0 になるという性質を使う
- 連続する 4 数の組 = 4k, 4k+1, 4k+2, 4k+3
- 4の倍数から始まることが最大のポイントで、4k からスタートすると必ず 0 になるのは、2進数で表したときに桁の上がり方がきれいに揃うから
- そこから +1, +2, +3 していった 4 つの数は、「下2桁だけが変化し、それより上の桁（4k の部分）は一切変化しない」 という状態になる
- 00, 01, 10, 11の繰り返し
- 「4 数の XOR が 0 になる」という性質を利用するときは、必ず 4 の倍数（4k）からスタートしているかが重要
- 逆にいうと、4の倍数からスタートしていないときは、法則に当てはまらない
- ただし、注意したいのは0からスタートする場合でも4の倍数として扱われる、つまり、k=0のときも連続する4数は排他的論理和の結果として 0 になる
- 同じ構造の隣り合う2数は XOR すると必ず 1 になる
- 直面した課題とその解決策をまとめておき、いつでも検索できる状態にしようと思った、過去の似たような場面があったときにすぐに引き出せるようにしよう

### 自学

- ハミング距離の考え方: 2つの値 a と b の XOR を計算（a ^ b）すると、「値が異なっているビットの場所だけが 1 になったビット列」が作られるため、その結果に含まれる 「1」の個数を数えること＝2つの値のハミング距離（何ビット違っているか）を測る ということになる
- 周辺知識ではなく、困った箇所をピンポイントで探してスピードを上げていこう
- ブライアン・カーニハン法: `bits & (bits - 1)` という操作を行ない、2進数の「一番右（下位）にある1」だけがピンポイントで0に書き換わるというビット演算の性質を利用する
- この方法だと、「1」が存在する個数分だけしかループが回らないため、線形探索に比べて高速に処理を終えることができる
- 10進数で `n` と `n-1` という隣り合う2つの数を2進数で並べると、必ず「一番右にある 1 と、それ以降の 0 がすべて反転する」という性質がある
- この性質を利用することで、2つの数同士で AND（`&`）をとると、真逆になった下位桁がすべて 0 にリセットされ、結果として「一番右の 1 だけが消えた数」へと変換される
- XOR交換による一時変数を使わないスワップ
- 「同じ数で2回 XOR（`^`）すると元に戻る」という性質($X \oplus Y \oplus Y = X$)
- スワップの実現方法: ①一時変数 ②XOR ③タプル
- 「毎日数が倍増する」というのは、ビットの視点で見ると「全体を 1 ビット左シフト（2倍）する」ということ
- 2進数では、数字全体を左に1桁ずらす（左シフトする）と、値が必ず2倍になる（10進数で末尾に 0 を付けると10倍になる仕組みと同じ）
- アメーバの増殖 = 1ビット左シフト（<< 1 で2倍にする操作）／アメーバの追加 = 最下位ビット（+1）の追加(1ビットの足し算)
