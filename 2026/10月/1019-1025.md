## 10/19(月)

- OSが知っているのは"指定された絶対パスや相対パスにあるファイルを実行することだけ"。そのため、PATH を解釈して文字列を組み立て、ファイルを総当たりで探す作業は、すべてシェル（プログラム）の仕事として行われている
- シェル自身がファイルを探すという説明は誤解を生む気がした。"誰が検索の手順を決めるのか"(シェル) と "誰がファイルへのアクセスを実現するのか"(OS) は別の話
- 標準ストリーム: プロセスが起動するときに用意される入出力経路、プログラムに用意された標準的な入出力経路。シェルやOSによって接続先が設定される
- ファイルディスクリプタ: その入出力先を参照するための番号（0、1、2）、プロセスがOSに対して開いた入出力先を指定するための番号
- カプセル化の目的は、すべてのメンバ変数を外部に公開することではなく、"必要な情報や操作だけ" を公開すること


## 10/20(火)

- コマンドライン引数はシェルが分解してから渡している
- Python の `sys.argv` はコマンドライン引数を格納した文字列のリストで、数値として使うにはキャストが必要
- ターミナルに入力された実行ファイルはリストに格納されないが、Pythonスクリプトのファイル名は `sys.argv[0]` に入る
- 前回のデータを残したままデータを上書きしてしまう処理が多く、予期せぬデータがまぎれてしまっていたので、既存のデータを削除してから処理をするようにVBAを大改修した。もはや作り直しに近かった。
- Sub と Function の最大の違いは、"値を呼び出し元に返す（returnする）かどうか" ということ
- ファイルを開いているのは "プロセス"
- ファイルディスクリプタはプロセス側が持っている番号


## 10/21(水)

- FDからファイルそのものに直接つながっているというよりは、FDを使ってカーネルが管理する入出力の仕組みにアクセスしていると考えられる
- `fork()` などでプロセスが作成される場合には、親プロセスのFDが子プロセスに引き継がれることもある
- Pythonの実行環境・ライブラリがFDを取得し、ファイルオブジェクトからの操作を適切な処理につなぐことで、Pythonプログラムではファイルオブジェクトを通じてファイル操作を直観的にできるようになる
- 「プログラムがOSにファイルを開く処理を依頼する→OSはファイルを開いてFDを返す→プログラム側の言語ランタイムやライブラリは、そのFDを利用するファイル操作用オブジェクトを提供する→その後、プログラムはそのオブジェクトのメソッドを呼び出し、必要に応じてOSにファイル操作を依頼する」という流れ
- FD番号はプロセスごとに管理されるため、別のプロセスで同じ番号を使っても問題ない。異なるプロセスが同じファイルを開くことも、通常は可能。同じファイルを開けることと、複数のプロセスが安全に書き込みできることは別の話。
- オープンファイル記述は "開いているファイルの操作状態" 。イメージとしては、ファイルそのものとは別に、そのファイルをどう操作しているかを記録する管理情報がある
- 同じファイルを参照していることと、同じオープンファイル記述を共有していることは別物。`fork()` や `dup()` によって同じオープンファイル記述を共有する場合、FDを引き継いだり複製したりすると、複数のFDが同じオープンファイル記述を参照することがある。この場合はファイルオフセットなども共有される。
- ファイルオフセット: ファイルの "先頭から" 何バイト進んだ位置にいるかを表す情報 = ファイル内のどこから次の読み書きを行うかを示す位置情報
- ファイルの先頭から毎回読み直していたら、ファイルの続きを効率よく読むことができないため、OSはオープンファイル記述にファイルオフセットなどの状態を保持している
- `open` はファイルを操作できる状態にし、`close` はその操作のために確立した接続を解放する処理。ファイルの場合は、OSが管理するファイルへのアクセス状態を終了させるイメージ = `open` によってファイルを操作するための状態を確立し、その状態を使って読み書きを行い、`close` によってそのFDを通じた操作を終了する
- ファイルディスクリプタリーク: プロセスが利用できる FD の数には上限があるため、最終的に新しいファイルやネットワーク接続を開けなくなることがある
- `f.read() ` の戻り値は、開き方がテキストモードかバイナリモードかで異なる
- テキストモード: str(文字列) - テキストファイル、設定ファイル → ファイル内容を文字列として扱う
- バイナリモード: bytes(バイト列) - 画像、PDF、音声ファイル → ファイル内容をバイト列として扱う
